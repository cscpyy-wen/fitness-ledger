# alpha11 舒适性迭代

本轮范围：在现有功能上改善信息顺序、留白、触控与长列表阅读。不是新一轮功能扩张；保留温暖浅色与绿色强调，不模仿 iOS 的系统控件或改动 Android 返回行为。

## 调整与验收点

| 问题 | 调整 | 验收方式 |
|---|---|---|
| 首页先看到方案设置，今日摄入在后 | 快捷入口之后直接显示营养卡；热量先于三项营养；压缩卡内重复留白 | 常规内容视口检查热量与三项；大字逐项滚动，系数与原值不变 |
| 饮食入口按钮垂直占高过多；长服务名挤压标题 | 常规宽度相册/手工并排，大字、窄屏或未完成手工草稿纵排；入口标题/服务自然换行 | 按钮至少 48 dp；大字不裁切，日期左右箭头可达 |
| 每种食物参考资料与本次摄入同等突出 | 本次克重、热量、宏量及份量依据常显；每 100 g、营养来源及热量口径按需展开 | 展开/收起只改变界面，无写账、无网络、无草稿；来源仍可完整读取 |
| 深色卡片背景与页面完全相同 | 深色 surface 提亮为 #1C211D，页面仍 #101411 | 实际深色截图检查层级、文字和按钮；不宣称完整无障碍认证 |
| 训练详情返回随历史组列表滚走 | 固定标题和 48 dp 返回按钮，日期与组记录独立滚动 | 24 组长列表、320 dp/1.5 倍字体到底后返回仍可见，系统返回仍有效 |

## 不变的边界

- 版本 0.6.0-alpha11 / versionCode 28；数据库 11，不新增迁移，不重算旧餐营养。
- 不新增实际进餐时间、餐别或已确认照片存储；“入账时间”仍不是实际进餐时间。
- 营养依据收起时仍显示份量依据和可靠性，不能把照片估算包装为精确测量。
- 相册仍会发送整餐照片给用户选择的服务，保存/切换服务本身不发请求；本轮不调用真实服务或消费用户 Key。
- 缺失明细的原合计仍保留；禁用更正/复制、二次确认删除等安全约束不变。
- 原位升级必须同包名、同长期签名且不卸载、不清数据；备份仍建议先做。

正式签名制品、测试数量、原位升级实测、截图和未验证边界统一记录于当前 `交付/验收报告.md`，不可用本设计说明替代结果。模拟器验证不代表小米真机、真实模型精度或完整 TalkBack 验收。
