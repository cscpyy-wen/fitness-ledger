# 小米云端称重接入 · alpha02

日期：2026-09-21。适用普通 S400、仅本人使用、已有小米运动健康云端记录的当前账号。此文取代早期 BLE / 企业接入申请作为当前实现路径，早期研究材料保留供追溯。

## 怎么用

1. 同签名覆盖安装主 App，不卸载旧版；先导出加密备份。
2. 身体 → 小米运动健康 → 连接并自动同步，阅读非官方会话通路说明。
3. 由本人在小米官方浏览器页面登录，再返回 App。验证工具与主 App 是不同沙箱，所以需在主 App 重新连接一次。
4. 自动保存近 7 天原值。同步设置里可补齐近 8 周、关闭后台或断开连接。
5. 以后称重先让小米端同步到云端。主 App 恢复前台会补查；需要即时检查时按“立即同步”。

不需要开发者模式、USB 调试、Root、无障碍读取、企业申请或小米密码交给助手。这里只读本人账号的 weight 数据，不读取其他 App 私有文件。

## 数据口径

- 只保存接口返回的体重（kg）、体脂率（%）、体水分（%）及测量时刻。缺失、零值或异常指标不推算，未返回骨量、肌肉等指标也不杜撰。
- 单账号账本绑定，不允许另一个账号静默混入。来源字段不能证明某台具体秤或识别家庭成员；本版按用户“仅我使用”设定，不提供多人自动分配。
- 去重键为账号指纹 + 来源 + 测量秒级时间。同日多次保留；重复同步幂等；相同键的云端修订更新原值。先前有值、后续缺失不会借用别次报告填补。
- 与手工身体表分开；不覆盖腰围、不改变方案参考体重、饮食目标、训练和 PR。原值不在 App 内编辑，可隐藏；隐藏标记随备份保留，重同步不会复活。
- 趋势每天一份代表值：优先当天手工体重，否则选当天最早小米称重。均重仅计算实测日期，显示覆盖天数，缺测不算零；这不是平均所有称次。
- 首次导入固定当时本地日期/时区偏移；后续换时区不静默移动旧记录日期。图表只显示近 4/8 周，已保存历史不按窗口删除。
- 查询本身不是全量镜像：分页限制、异常记录或部分请求失败会提示不完整；空响应不删除已有历史，云端删除也不会自动删除本机已导入记录。补齐最多近 56 天，未实现全部历史下载。

## 自动同步与隐私

- 未连接时不查询小米。明示同意后会话使用 Android Keystore AES-256-GCM 加密存于独立偏好设置，业务备份和系统迁移均不包含会话。密码、验证码、passToken 不持久保存。
- 这是非官方会话接口，不是限定体重权限的官方 OAuth；会话本身可能拥有更广账号权限，App 实际仅请求当前账号体重。云端数据区固定中国大陆；接口变更、风控及账号状态可能使功能失效。
- 打开 App 自动检查有 15 分钟节流；手动“立即同步”不受此节流。后台使用 JobScheduler 约 2 小时周期，需联网且电池不低；系统可推迟。强行停止 App 或 HyperOS 限制后台可能使任务不运行，不承诺站上秤立即到账。
- 登录会话本机最长保留 30 天，上游可能更早失效；过期提示重新连接，历史保留。不会靠自动重试密码或绕过验证维持登录。
- 断开先清除本机持久凭据、停后台，再关闭在途请求；迟到结果不得写入。断开不注销浏览器账号，也不是服务端会话撤销。恢复备份使旧同步失效，需重新连接。
- 数据库 v11 新增两张云端表；加密备份包含数据及隐藏状态、排除凭据；兼容 v10 备份升级为空云端表。备份恢复不合并而是替换整个账本，遵循原有确认流程。

## 验证边界

用户在独立探针报告“读到了。没有问题”，只据此确认当前账号前台读取可用。主 App 的数据库事务、去重、修订、手工共存、隐藏、账号冲突、时区、备份迁移、加密会话、断开/恢复竞争、过期及关闭后台路径使用合成响应自动化验证。最终数量和签名包身份见顶层交付报告。

尚未声称主 App 在 Xiaomi 15 Pro 上完成全天后台实测，也未核验用户全部报告。无真实账号会话进入测试、仓库、日志或交付证据。模拟器截图全部是合成示例。
