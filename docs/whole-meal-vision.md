# 整餐拍照与外置视觉模型

更新：2026-09-22，v0.6.0-alpha09 / code 26 / 数据库 v11。

## 怎么用

1. 在“饮食 → 连接外置大模型”或“整餐拍一次 → 管理模型服务”选择 Qwen、DeepSeek、GLM 或自定义入口，填入 API 地址、视觉模型 ID 和自己的 API Key，并确认上传目的地。可保存多条、在饮食页切换；每条密钥独立。只在手机填写密钥，不发送到聊天。兼容差异见[多服务说明](multi-provider-vision.md)。
2. 百炼用户可直接粘贴创建 Key 后显示的业务空间 API Host，App 自动补全兼容路径。模型 ID 默认 `qwen3-vl-plus`，可换成该账号有权限且支持图片的 Chat Completions 模型。其他兼容服务填写完整 Base URL（含 `/v1` 等路径）或最终 `/chat/completions` 地址。
3. 保存后返回饮食，把整餐的饭、菜、饮品拍在同一张图里；或从相册选一张。保存设置本身不调用模型、不计费，也不等于连接实测成功。
4. 结果按多道菜预填名称、可食份量、碳水、蛋白质、脂肪和总热量。明显错误可以编辑，没吃的项目删除，漏项手工补充；合餐按“我吃了多少？”将**当前显示份量**调整为 ¼、½、¾，或用编辑按钮输入克重。该操作不调用模型；不是按原始整盘反复选择百分比。
5. 核对后整餐确认入账。未确认、识别失败、网络错误、无食物都不会增加摄入。重复确认只记一次。

无需自己的服务器、USB、开发者模式、Root 或无障碍权限。API 开通、套餐/费用和模型权限属于本人账号，App 不包含共享密钥，不替用户开通付费服务。

可选：在设置的“附加提示词”中保存已知份量、餐盘或烹调背景；所有服务共用，最多 2000 字符。食堂餐盘示例仅预填，核对后才保存；模型被要求在结果说明中标明参照是否采用。[完整说明](meal-analysis-prompts.md)。

## 估算与安全边界

- 这是视觉模型最佳估计，不是电子秤。单张图片不能可靠测定油、配方、遮挡、餐具容量或实际吃掉多少；克重范围也不是经标定的置信区间。
- 整菜的每 100 g 估值要求包含常见油和酱汁，提示模型不要同时列整菜与原料/油造成重复计算。但模型仍可能犯错，需核对。
- 直连返回的热量由 App 以 `4 × 碳水 + 4 × 蛋白质 + 9 × 脂肪` 统一折算，忽略模型另报的矛盾总热量。营养来源固定写“视觉模型估算”，不能伪装成已经查询的权威数据库或称重值。每项/整餐不能高于 C；D 级仍需补充编辑。
- EXIF 去除、图片压缩后，将照片、内置提示和用户已保存的附加提示词发送给所配置服务。不会自动附带身体、训练、小米账号数据；不要在附加提示中写入不希望上传的隐私信息。供应商的留存和删除规则以其政策为准，不承诺零留存。
- API Key 在手机 Android Keystore 加密，绑定精确目标地址和连接方式；不入 APK、备份、全局 UI 状态或可恢复表单。更换地址/协议须重新输入，所有 3xx 拒绝跟随。
- 一次显式识别发起一次应用层请求；应用不自动重试或切换供应商。连接超时 12 秒，直连读取超时 75 秒，响应最多 256 KiB。供应商可能忽略幂等头，手动重试可能再次计费；建议在控制台设置消费提醒/预算。
- 相机或相册首次请求发出前，先持久化可恢复照片草稿；进程中断后仅恢复草稿，不自动重发付费请求。旧版本遗留的 ANALYZING 相机任务也只做本地恢复。用户可以明确重试或手工补录。
- 识别失败保留照片，可直接进入设置修正后返回重试；旧离线草稿可转外置识别，重试失败保留原食物与修改。无连接时不再回退到单菜分类器或演示营养。
- SQLite 仍 v11；小米同步、减脂系数、既有饮食、训练和 PR 不改动。备份继续排除识别连接、密钥与小米凭据，但包含用户填写的附加提示词；恢复旧备份时该字段为空。

## 研究依据与验证口径

阿里云当前文档支持图片输入、多个可见目标理解和结构化输出；这支持整餐识别的技术路线，**不证明营养或重量准确率**。[视觉理解](https://help.aliyun.com/zh/model-studio/vision)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

百炼推荐业务空间专属 API 域名；API Key 所属地域和服务地址应一致。默认模型只是可修改的兼容示例，不代表用户账号已开通。[地域与接入域名](https://help.aliyun.com/zh/model-studio/regions/)、[API Key 获取](https://help.aliyun.com/zh/model-studio/get-api-key)。

自动化覆盖合成三菜响应、请求只含一张图、单位和宏量/热量一致性、C/D 强制证据边界、无食物/截断/越界拒绝、未确认不入账、整餐幂等提交、密钥加密与换址隔离、备份排除、上传同意和份量编辑。使用合成响应，不读取或消耗真实付费 Key。真实供应商联网兼容性与常吃中餐称重误差须本人配置后验证；不要把模拟器通过写成真实识别准确率。
